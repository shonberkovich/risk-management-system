# תסריט הדגמה (Demo Script) — RMIS

מסמך Walkthrough המיועד למרצה/בודק של הקורס, ומנחה צעד-אחר-צעד כיצד להריץ הדגמה מקצה-לקצה של המערכת: מהקמת סביבה ריקה ועד הצגת כל היכולות המרכזיות — RBAC, ניהול נכסים וסיכונים, דיווח אירועים עם AI/GPS/EXIF/Offline, תביעות, ניהול משתמשים, התראות ואינטגרציות, אנליטיקה (VaR, השתתפות עצמית, מפת סיכונים), דוחות מודפסים/Excel, וסייר ה-AI (Copilot).

כל הצעדים אומתו מול קוד המקור בפועל (routes ב-`frontend/src/App.tsx`, פריטי ניווט ב-`frontend/src/components/Layout.tsx`, תוויות כפתורים בקבצי ה-`pages`/`components` הרלוונטיים, ומשתמשי ה-Demo ב-`backend/app/seed.py`) — לא הועתק כלשון-אחת מ-`TODO_SPEC.md`.

## 0. הכנה — הקמת סביבה והרצת המערכת

1. **בסיס הנתונים (פעם אחת, על DB ריק/חדש):**
   ```bash
   sqlcmd -S "(localdb)\MSSQLLocalDB" -C -i sql\schema.sql
   ```
2. **זריעת נתוני דמו** (מ-`backend/`, אחרי `venv\Scripts\activate`):
   ```bash
   python -m app.seed
   ```
   הסקריפט מוחק ומאכלס מחדש את כל הטבלאות (סדר FK-safe) ומדפיס בסיום כמה שורות נוצרו בכל טבלה.
3. **מפתח AI (אופציונלי אך מומלץ להדגמה מלאה):** קבעו `ANTHROPIC_API_KEY` ב-`backend/.env` (גיטיגנור). **בלעדיו** כל נקודות הקצה תחת `/api/ai/*` (סיווג אירוע, תקציר מנהלים, סייר ה-AI) יחזירו 503 מנומס במקום לקרוס — ראו הערה בסעיף 8 ו-11 להלן היכן זה בא לידי ביטוי.
4. **הרצת שרתים** (שני טרמינלים נפרדים, או `preview_start` עם configs `backend`/`frontend` מ-`.claude/launch.json`):
   ```bash
   # backend/  (venv מופעל)
   uvicorn app.main:app --reload          # http://localhost:8000  (Swagger: /docs)
   # frontend/
   npm run dev                             # http://localhost:5173 (proxy /api -> :8000)
   ```
5. פתחו דפדפן בכתובת **http://localhost:5173** — אמורים לראות מסך התחברות ("🏢 RMIS — מערכת ניהול סיכונים — התחברות") עם שדות "אימייל"/"סיסמה".

## 1. RBAC — הדגמת הרשאות לפי תפקיד

המטרה: להראות שתפריט הניווט (וגישת ה-API מאחוריו) משתנה לפי תפקיד, לא רק "מסך אחד לכולם".

1. התחברו כ-**עומר בר** (`omer.bar@company.co.il`, FIELD_WORKER). שימו לב:
   - דף הבית (`/`) מציג **דשבורד שטח מצומצם** (ראו סעיף 9) — ללא KPIs כספיים כלל.
   - תפריט הניווט מציג רק: דשבורד, דיווח אירוע, ניהול אירועים, מסמכים, אינטגרציות (רק חלק ה"מזג אוויר" באמת רלוונטי לו) — **אין** "נכסים", "תביעות", "פוליסות", "דוחות", "ניהול משתמשים" וכו'.
2. התנתקו (כפתור היציאה בפינת ה-AppBar) והתחברו כ-**דנה כהן** (RISK_MANAGER). שימו לב שכעת דף הבית מציג את **דשבורד המנהלים המלא** (KPIs, מפה, מטריצת סיכונים, גרפים), והתפריט חושף גם נכסים/אירועים/תביעות/פוליסות/הפחתת סיכון/סימולציה/השתתפות עצמית/התראות/דוחות/תאימות.
3. התחברו כ-**אדמין מערכת** (ADMIN). זהו התפקיד היחיד שרואה גם "יומן ביקורת", "ניהול משתמשים" ו-"ניהול הרשאות" בתפריט (ראו `Layout.tsx`: `user?.role === "ADMIN"` תמיד חושף את כל הפריטים, ללא תלות ברשימת ה-`roles` שמוגדרת לכל פריט).
4. **נקודה להדגשה בפני הכיתה:** ה-RBAC לא מסתפק בהסתרת כפתור ב-UI — כל נקודת קצה בשרת (`backend/app/routers/*.py`) אוכפת `require_roles(...)` בעצמה; ניתן להראות זאת בקצרה דרך Swagger (`/docs`) — למשל ניסיון להריץ `GET /api/users/admin` ללא טוקן ADMIN מחזיר 403.

## 2. ניהול נכסים (Properties) וסקר סיכונים

**המשיכו כ-דנה כהן (RISK_MANAGER) או התחברו כ-מיכל אזולאי (PROPERTY_MANAGER).**

1. נווטו ל-**"נכסים"** (`/properties`). מוצגת רשימת 15 הנכסים מה-Seed ככרטיסים לחיצים, עם כפתור **"נכס חדש"** למעלה (מוסתר למשתמש ללא הרשאת כתיבה).
2. לחצו על כרטיס נכס — כל הכרטיס לחיץ (לא רק אייקון) וינווט אתכם ל-**תיק נכס** (`/properties/:id`, `PropertyDetail.tsx`). כאן מוצגים:
   - כרטיס פרטי הנכס, עם כפתור עריכה (פותח את `PropertyDialog.tsx`, אותו דיאלוג "נכס חדש"/"עריכת נכס").
   - כרטיס **פוליסה פעילה** משויכת לנכס.
   - כרטיס **סקר סיכונים** — אם קיים, מוצג ציוני הצפה/שריפה/רעידת אדמה, MFL, מתזים. כפתור בכרטיס מציג **"עדכון סקר"** אם כבר קיים סקר, או **"סקר חדש"** אם אין — פותח את `RiskSurveyDialog.tsx` עם סליידרים (1–5) לכל סוג סיכון, שדה MFL, מתג מתזים והערות.
   - כרטיס **מסמכים** מצורף לנכס (רשימה + העלאה).
3. **להדגמה:** ערכו סקר סיכונים קיים (שנו ציון הצפה), שמרו, וחזרו לרשימת הנכסים — ניתן לחזור לאותו תיק נכס ולוודא שהערך התעדכן.

## 3. דיווח אירוע — Wizard מלא (AI, GPS, EXIF)

זהו החלק המרשים ביותר להדגמה — מומלץ לבצע כ-**רונית שמעוני / עומר בר (FIELD_WORKER)**, ששניהם רואים את "דיווח אירוע" בתפריט וזהו התרחיש המרכזי בשבילם.

נווטו ל-**"דיווח אירוע"** (`/report-incident`, `IncidentReport.tsx`). האשף בנוי 4 שלבים (`Stepper`): "מיקום וזיהוי הנכס" → "פרטי הנזק והחומרה" → "אומדן כספי ותיאור" → "תיעוד ושליחה".

**שלב 1 — "מיקום וזיהוי הנכס":**
- כפתור **"אתר את מיקומי והצע נכסים קרובים"** (אייקון מיקום) מפעיל את Browser Geolocation API. אם הדפדפן מאשר גישה למיקום, מוצגת רשימת עד 5 נכסים קרובים (רדיוס 15 ק"מ, ממוינים לפי מרחק) כ-Chips, **והנכס הקרוב ביותר נבחר אוטומטית** לשדה "נכס" למטה (ללא צורך ללחוץ). בחירה ידנית על Chip אחר, או ב-Autocomplete עצמו, גוברת על הבחירה האוטומטית.
- אם הדגמה חיה עם GPS אמיתי לא זמינה (למשל מחשב שולחני ללא הרשאת מיקום), ניתן לדלג ולבחור נכס ידנית מה-Autocomplete "נכס" — הזרימה תמשיך לעבוד זהה.
- שדה "תאריך ושעת האירוע".

**שלב 2 — "פרטי הנזק והחומרה":** בחירת סוג מפגע (hazard type) וחומרה דרך `ToggleButtonGroup`.

**שלב 3 — "אומדן כספי ותיאור":**
- שדה חופשי "תיאור האירוע" (לדוגמה: *"פיצוץ בצינור מים ראשי בקומה 1 שגרם להצפה באזור האריזה..."*).
- כפתור **"נתח עם AI"** (אייקון ✨AutoAwesome) קורא ל-`POST /api/ai/classify-incident` על הטקסט שהוזן, וממלא אוטומטית את סוג המפגע/חומרה/הערכת נזק (ואם רלוונטי — "צפוי אובדן רווחים"). מוצגת קופסת "ניתוח AI" עם רמת ביטחון ונימוק.
  - **אם `ANTHROPIC_API_KEY` לא מוגדר בסביבה**, הכפתור עדיין לחיץ אך הבקשה תיכשל בצורה מבוקרת — מוצגת הודעה *"ניתוח ה-AI נכשל. ניתן להמשיך ולמלא ידנית."* — נקודה טובה להדגים "Graceful Degradation" ולא באג.
- שדה "הערכת נזק ראשונית (₪)".

**שלב 4 — "תיעוד ושליחה":**
- העלאת תמונות/מסמכים דרך `MediaUploader`. **לכל תמונה שמצורפת מחולצת EXIF בצד הלקוח** (ספריית `exifr`) — אם לתמונה יש נתוני GPS ו/או תאריך צילום, הם מוצגים כ-caption קטן מתחת לשם הקובץ (שעון + תאריך צילום, סמל מיקום + קואורדינטות). תמונות ללא EXIF שמיש (צילומי מסך, PNG) פשוט לא מציגות caption — התנהגות תקינה, לא שגיאה.
  - **טיפ הדגמה:** לתמונה עם EXIF תקין השתמשו בתמונה שצולמה בפועל בסמארטפון עם שירותי מיקום מופעלים; תמונת מסך (Screenshot) לא תכיל GPS.
- שליחה סופית יוצרת את האירוע (`Incidents`).

### הדגמת מצב Offline (סנכרון רקע)

1. פתחו את כלי הפיתוח בדפדפן ועברו למצב "Offline" (Network throttling), או נתקו את חיבור הרשת בפועל.
2. שימו לב ל-Chip הקטן ב-AppBar (`ConnectionStatus`) שמשתנה מ-"מקוון" ל-**"לא מקוון"**.
3. מלאו ושלחו טופס דיווח אירוע חדש (או ערכו טיוטה קיימת) במצב מנותק — הבקשה נשמרת מקומית (IndexedDB) בתור סנכרון במקום להיכשל, וה-Chip יעדכן ל-"X ממתינים לסנכרון".
4. חברו את הרשת חזרה — הסנכרון רץ אוטומטית (או לחצו על ה-Chip לניסיון סנכרון ידני); לאחר הצלחה ה-Chip חוזר ל-"מקוון" ללא פריטים ממתינים, וניתן לפתוח את "ניהול אירועים" ולוודא שהדיווח שנוצר במצב לא-מקוון קיים בפועל בשרת.

## 5. ניהול משתמשים והרשאות (ADMIN בלבד)

**התחברו כ-אדמין מערכת.**

1. **"ניהול משתמשים"** (`/users`, `Users.tsx`) — טבלת 9 המשתמשים (שם/אימייל/תפקיד/סטטוס/תאריך יצירה). כפתור **"משתמש חדש"** פותח את `UserDialog.tsx` (יצירה/עריכה, כולל שינוי תפקיד, איפוס סיסמה אופציונלי, הפעלה/השבתה). לחיצה על שורה קיימת פותחת אותו דיאלוג לעריכה.
   - **להדגמה:** השביתו זמנית משתמש (למשל "יוסי מזרחי") ← נסו להתחבר איתו ← ההתחברות/הבקשה הבאה נחסמת מיידית (נאכף גם על טוקן שכבר הונפק, לא רק בכניסה הבאה) ← החזירו אותו לפעיל בסיום ההדגמה.
2. **"ניהול הרשאות"** (`/roles`, `Roles.tsx`) — קטלוג `Role_Permissions` (תפקיד/מפתח הרשאה/תיאור), עם סינון לפי תפקיד והוספה/עריכה/מחיקה. **חשוב להדגיש למרצה:** מסך זה הוא תיעוד קטלוגי בלבד — האכיפה בפועל של RBAC ממשיכה להתבצע דרך `require_roles()` מקושח בקוד השרת, לא נקראת דינמית מהטבלה הזו (ראו הערת ההיקף בקוד `role_permissions.py`).
3. **"יומן ביקורת"** (`/audit-log`) — עוד מסך ADMIN-בלבד, מציג את `Audit_Log` (מי שינה מה ומתי).

## 6. התראות ואינטגרציות

**גלוי בתפריט ל-RISK_MANAGER/CFO/ADMIN ("התראות"), ולכולם ("אינטגרציות", כי חלק ממנו — מזג אוויר — פתוח לכל תפקיד מחובר).**

1. **"התראות"** (`/notifications`, `Notifications.tsx`):
   - תצוגה מקדימה (Preview) של מי יקבל התראה כרגע.
   - כפתור **"שליחה עכשיו"** (מבקש אישור) שולח בפועל (מדומה) ורושם ל-Notification_Log.
   - יומן שליחות היסטורי, וניהול נמענים (`Notification_Recipients`) — הוספה/עריכה/מחיקה, כתיבה ADMIN-בלבד.
2. **"אינטגרציות"** (`/integrations`, `Integrations.tsx`) — ארבעה אזורים, כולם מדומים (Simulated) ומתועדים כך במפורש בקוד:
   - **ERP** — ערכי ספרים + כפתור **"רישום קבלות תביעות"**.
   - **GIS** — שכבות סיכון מול הסקר הפנימי.
   - **מזג אוויר** — התראות אזוריות מדומות (פתוח לכל תפקיד, כולל FIELD_WORKER).
   - **מדדים כלכליים** — הצעות עדכון שווי כינון.
3. **קישור בין הסעיפים:** באנר מזג האוויר (`AlertsBanner`) מוצג גם בדשבורד הראשי וגם בדשבורד השטח — הדגימו זאת בשתי הכניסות (ADMIN מול FIELD_WORKER) כדי להראות שהוא זמין לכולם אך התוכן הפיננסי סביבו לא.

## 7. אנליטיקה: VaR, השתתפות עצמית, מפת סיכונים

**כ-דנה כהן (RISK_MANAGER) או אבי לוי (CFO).**

1. **"סימולציה ו-VaR"** (`/simulation`, `Simulation.tsx`): בחרו היקף (Portfolio מלא או נכס בודד), הזיזו את שני הסליידרים — **מספר הרצות** (1,000–100,000) ו-**אופק בשנים** (1–50) — ולחצו **"הרץ סימולציה"**. מוצגים KPIs (הפסד שנתי צפוי, VaR95/VaR99) והיסטוגרמת התפלגות נזק (Monte Carlo) עם קווי ייחוס ל-VaR.
2. **"השתתפות עצמית"** (`/retention`, `Retention.tsx` + `RetentionCalculator.tsx`): בחרו נכס מבוטח, הזינו/אשרו נזק משוער (ברירת מחדל מה-MFL), לחצו **"חשב המלצה"** — מוצג Chip **ABSORB** (לספוג) או **CLAIM** (לתבוע) עם שתי כרטיסיות השוואת עלות. כפתור **"ייצוא ל-Excel"** מייצא את חישוב ההשוואה.
3. **מפת הסיכונים** — משולבת בתוך **דשבורד המנהלים הראשי** (`/`, `RiskMap.tsx` — אין route נפרד ל-"מפה"). כוללת **בקרת שכבות (Layer Control)** — מתגי הדלקה/כיבוי: "נכסים", "אירועים פעילים (N)", "אזורי הצפה", "אזורי שריפה", ואשכולות חשיפה (TIV clusters). לחיצה על סימון נכס פותחת Popup עם פרטי הנכס וכפתור **"מעבר לתיק הנכס"** שמנווט ישירות ל-`/properties/:id`.

## 8. דוחות: Excel, PDF, חשיפה לפי אזור, תאימות

**"דוחות"** (`/reports`, `Reports.tsx`, גלוי ל-RISK_MANAGER/CFO):

1. **דוח רגולטורי** — כולל גרף חדש **חשיפה לפי אזור** (`ExposureByRegionChart.tsx`, TIV מול MFL לכל אזור — צפון/מרכז/דרום) וטבלת מגמה רב-שנתית.
2. כפתור **"ייצוא דוח חשיפה ל-Excel"** — חוברת עם גיליון חשיפה-לפי-אזור וגיליון מגמה רב-שנתית.
3. כפתור **"ייצוא ל-PDF"** — Executive Report מודפס (html2canvas + jsPDF) הכולל KPIs, גרפים וסימולציה אם רצה.
4. **תקציר מנהלים AI** — אם `ANTHROPIC_API_KEY` מוגדר, ניתן להריץ תקציר Streaming שנוצר על ידי Claude מתוך נתוני ה-KPIs בפועל; ללא מפתח מוצגת הודעת 503 מנומסת.
5. **"תאימות ISO 31000"** (`/compliance`, `Compliance.tsx`, גלוי ל-RISK_MANAGER/RISK_OFFICER/CFO) — דוח תאימות משולב הכולל כעת גם סעיפי **Solvency II (Pillar II)** וגם **חוזר ניהול סיכונים של רשות שוק ההון**, לצד 5 הסעיפים המקוריים של ISO 31000:2018 — כל סעיף מתויג במסך עם שם המסגרת שלו.
6. **"הפחתת סיכון"** (`/mitigation`, `Mitigation.tsx`, גלוי ל-RISK_MANAGER/PROPERTY_MANAGER) — טבלת משימות מיטיגציה + KPIs (משימות פתוחות/באיחור, עלות, חיסכון שנתי, ROI ממוצע), עם כפתור **"ייצוא ל-PDF"** משלה (`MitigationReportPrintable.tsx`).

## 9. דשבורד שטח (Field Worker)

**התחברו כ-רונית שמעוני או עומר בר (FIELD_WORKER).**

דף הבית (`/`) מציג עבורם `FieldWorkerDashboard.tsx` במקום דשבורד המנהלים — **ללא נתון כספי אחד** (לא TIV/MFL, לא Loss Ratio, לא VaR/מטריצת סיכונים, לא Cashflow), כי גם בצד השרת ל-FIELD_WORKER אין גישה לנקודות הקצה הפיננסיות (`_FINANCIAL_READ_ROLES`). כולל:
- כרטיס חיבור/סנכרון גדול (אותו מנגנון `ConnectionStatus`/syncQueue).
- כפתור בולט "דיווח אירוע חדש".
- רשימת 12 האירועים האחרונים (קוד, סטטוס, חומרה, סוג מפגע, תיוג "טיוטה" אם רלוונטי), כל שורה מקושרת לתיק האירוע.

השוו זאת ישירות מול דשבורד המנהלים (סעיף 1) כדי להמחיש את ה-RBAC ברמת מסך שלם, לא רק ברמת widget בודד.

## 11. סייר ה-AI (Copilot Widget)

זמין מכל מסך מאובטח — כפתור FAB צף (פינה תחתונה) שמורכב פעם אחת ב-`Layout.tsx`.

1. לחצו על ה-FAB — נפתח פאנל צ'אט קטן עם שאלות מוצעות (למשל: "מהו סך שווי החשיפה הכולל (TIV)?", נכסי סיכון גבוה, Loss Ratio).
2. שאלה שנשלחת פונה ל-`POST /api/ai/ask` (`services/llm.py`) — **המודל אינו כותב SQL**; הוא בוחר אחד מחמישה כלים מוגדרים-מראש (`get_kpis`, `query_properties`, `query_claims`, `query_incidents`, `query_mitigation_tasks`) עם פרמטרים בלבד. שווה להדגיש זאת למרצה כעיצוב אבטחה מכוון (ראו `CLAUDE.md`).
3. **ללא `ANTHROPIC_API_KEY`** — השאלה תוחזר עם הודעת 503 מנומסת ("שירות ה-AI אינו מוגדר") במקום שגיאה גולמית — עדות נוספת ל-Graceful Degradation שחוזרת בכל תכונת AI במערכת (סיווג אירוע, תקציר מנהלים, וכעת גם כאן).

## 12. סיכום — Checklist להדגמה מהירה (≈20–25 דקות)

1. Login כ-FIELD_WORKER → דשבורד שטח מצומצם → Login כ-ADMIN → דשבורד מנהלים מלא (RBAC).
2. נכסים → תיק נכס → עדכון סקר סיכונים.
3. דיווח אירוע: GPS אוטומטי → ניתוח AI → העלאת תמונה עם EXIF → שליחה.
4. (אופציונלי) ניתוק רשת → דיווח נוסף → חיבור מחדש → סנכרון אוטומטי.
5. תביעות → ייצוא ל-Excel.
6. ניהול משתמשים/הרשאות (ADMIN).
7. התראות (Preview + שליחה) ואינטגרציות (ERP/GIS/מזג אוויר).
8. סימולציה VaR עם סליידרים; מחשבון השתתפות עצמית.
9. מפת סיכונים: הפעלת/כיבוי שכבות, Popup → מעבר לתיק נכס.
10. דוחות: גרף חשיפה לפי אזור, ייצוא Excel/PDF, דוח תאימות (ISO/Solvency II/רשות שוק ההון).
11. סייר ה-AI: שאלה מוצעת מה-FAB.

**הערת תלות חשובה:** צעדים 3 (ניתוח AI), 10 (תקציר מנהלים AI) ו-11 (סייר ה-AI) דורשים `ANTHROPIC_API_KEY` תקין ב-`backend/.env` כדי להדגים תשובה אמיתית מהמודל — בלעדיו הזרימה עדיין שלמה ותקינה (503 מנומס בכל מקום), אך ההדגמה לא תראה בפועל את תוצרי ה-AI עצמם.
